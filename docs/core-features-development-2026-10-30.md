# 核心功能引入与全流程验证

本轮围绕已恢复的历史要求实施四项核心能力：请求活动与响应报告用量、配置漂移与安全断开、模型搜索/收藏/最近使用、具名多客户端配置方案。保持四步连接主流程、真实模型查询、原配置及历史保护、唯一目标自动选择和多目录明确选择。

## 功能与实际边界

| 功能 | 当前实现 | 保护边界 |
| --- | --- | --- |
| 请求活动 | 按客户端查看 HTTP、完成/失败/中断/未完成/取消、耗时和已报告 token；本轮补充 token 上限及嵌套失败判断 | 最近 200 条仅内存，不保存对话、工具参数、密钥、原始错误；请求模型不证明上游物理模型 |
| 配置保护 | 八客户端的自有字段检测、恢复预览、确认断开、原始值保留、后加设置保留、冲突拒绝、回读与故障恢复 | 旧版没有记录的原值不能倒推；任何外部修改导致预览失效，不能自动覆盖用户连接修改 |
| 模型选择 | 搜索、全部/收藏/最近筛选、当前模型保留，按客户端与已保存连接隔离 | 仅保存模型/客户端/连接 ID 和时间；未保存连接不持久化，配置失败不记录最近使用 |
| 具名方案 | 选择已配置客户端保存组合，更新/删除、逐客户端预览、一次批量事务、故障回滚与重启恢复 | 方案不含密钥和路径；仅应用到当前已确认位置；预览绑定供应商、文件与配置版本；未恢复事务阻止后续写入 |

详细使用见 [配置保护](../app/docs/configuration-safety.md)、[模型与方案](../app/docs/model-profiles.md)、[请求活动](../app/docs/request-activity.md)。方案应用后需要客户端重新加载，旧的文件工具验证状态会清除；不会把“文件配置已写入”提升为“真实客户端已通过”。

## 恢复记录与敏感信息

字段所有权和故障恢复必须保存修改前的配置，其中可能含接入前的凭据。这些数据仅存程序旁私有 `data/`；不能进入源码包、发布包或日志。新增 `runtime-integrity.key` 用于 HMAC-SHA256 完整性认证，记录按客户端及用途隔离，缺失密钥、内容篡改或跨用途重放均停止写入。认证保护不等于加密，能读取完整私有数据的本机用户仍可读取恢复内容。

打包器排除这些运行时文件，包审计在任何目录位置拒绝它们，防止误复制到非 data 位置。公开 IPC 只返回固定文件类别、字段计数和不可逆预览指纹，不返回恢复原文或密钥。已知敏感值扫描覆盖指定私有输入的多种编码以及二进制和 ZIP 解压成员，但不证明未知凭据、任意编码、图片文字或非 ZIP 压缩资源全部不存在。

## 本轮验证流程

1. 使用工作区 `release-env.ps1`，将可控临时目录、缓存、编译与浏览器数据固定在 G 盘。独立测试验证 32 个变量以及 Node/Python/PowerShell 子进程继承和实际 TEMP 写点。
2. 最终源码执行 TypeScript、全量前端、教程一致性、Rustfmt、全量 Rust 无桌面特性、桌面三测试程序、全特性 Clippy。
3. 构建正式 UI、desktop/core，生成源码前后摘要及程序哈希；构建期间源码变化即拒绝验收。
4. 最终编译 CLI 跑八客户端合成原生配置完整链：配置、保存两套方案、批量切换回读、过期预览拒绝、保留人工设置、八次安全断开、历史字节检查、方案删除。这是本地集成，不等同官方客户端验收。
5. 正式 dist 模拟 IPC 验证完整页面交互、全局操作互锁、深浅主题与桌面/窄屏布局及无障碍；原生程序需要单独验证。
6. 使用最终程序和新 G 沙盒进行真实模型发现、八个官方客户端配置及真实文件写读。初轮使用 `gpt-6.1-sol / ultra`，不自动换模型或降档；用户随后仅授权 AE 隔离接入客户端使用 `xhigh`，后续新轮次按该指令执行。本机 Codex 配置、认证与当前会话设置均不改动。
7. 审计最终程序、源码、UI、敏感信息及 ZIP 每成员字节，保留失败和后续复验的不同收据，只清理明确本轮归属的临时目录。

验收收据以 `artifacts/acceptance/core-features-20261030/` 与本轮独立 build audit 的实际 JSON 为准；验证命令与边界见[验收说明](core-features-acceptance-2026-10-30.md)。未执行或失败的项目保持未通过，不能根据先前发布、模拟服务或旧版本收据声称功能 100% 正常。
