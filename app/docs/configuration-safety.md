# 配置漂移检测与安全断开

“配置保护与安全断开”按客户端检查 AE 最近实际写过的连接字段。八个客户端使用同一所有权契约，JSON/JSONC、TOML 和已支持的 YAML 继续复用原有解析及保留源码的编辑器。

## 所有权与恢复

- 首次成功配置记录修改前和修改后的状态。之后切换模型会更新最近写入值，保留第一次接入前的字段原值。
- 检查只比较 AE 修改的语义字段；用户新增的其他键、注释和设置不会单独构成漂移。数组按索引比较自有字段；新增尾部行可保留，移动或改写自有行会阻止恢复。
- 断开仅清理 AE 新建且已经为空的受管祖先对象；用户后来新增的空对象、空表及空数组成员保留。合法 TOML 空表与内联表不会被全局清理。
- 预览显示配置文件类别及自有字段数，不显示密钥、原文或实际路径。预览令牌同时绑定所有权记录、当前文件字节和客户端选择；预览后任何文件或选择变化都使令牌失效。
- 确认断开后，先检查全部文件，再只还原自有字段，并移除该客户端在 `agent-selection.json` 中的选择。其他客户端的选择不变。恢复结果逐文件回读核对。
- 所有自有字段都仍与 AE 最近写入一致时才能恢复。任何冲突、损坏文件、未经选择的路径或 profile 变化都会停止写入；不会自动“修好”用户后来改的连接。
- 原生配置、JSONC/YAML 未修改源码和 TOML 原 Item 的注释尽量按原样保留。当前内容与 AE 最后写入完全一致时，可直接恢复首次原文件字节；首次不存在的文件可删除。已添加其他设置的文件会保留。
- 恢复不会删除历史、工作目录或会话数据库。ZCode 的 state 仅涉及原配置阶段已授权并修改的内置代理模型选择。

## 旧版本边界

只有本版本开始跟踪的配置才有恢复记录。旧配置显示“尚无恢复记录”，不能声称找回此前未保存的原值。再次确认连接可以开始跟踪之后的字段修改，但不会倒推出更早的配置。

私有 profile 的原生连接文件及便携启动环境也可恢复。首次不存在的启动环境会移除，保留的启动器因缺少该环境而停止，避免旧启动器继续连接已断开的网关。客户端历史目录会保留；请重新加载或关闭仍在运行的客户端。

## 数据与事务

所有权记录为便携数据目录中的 `agent-ownership-<client>.json`，其中包含恢复所需的原配置值，按私有数据写入。它可能包含接入前已有的凭据，因此必须与数据库同等保护，不能加入公开源码、分享包或日志。

所有权基线、pending 及断开恢复记录使用共享私有 `runtime-integrity.key` 进行 HMAC-SHA256 完整性校验，并绑定记录用途和客户端。被修改、替换用途、缺少私钥或没有签名的记录会停止恢复；不会把被篡改的原值写回原客户端。完整性密钥同样保留在 G 盘私有数据目录，禁止进入分享包。

配置写入先保存 pending 所有权记录，复用原有配置事务。重启时先完成或回滚原生配置事务，再根据全部实际文件是否与预计写入一致决定是否提交所有权记录。

断开使用 `agent-disconnect.pending.json`。目标路径从当前保存的客户端选择与已验证的固定配置槽重新解析，恢复计划从所有权记录复算，拒绝替换路径或恢复内容。事务完成前保留原客户端选择作为授权，最后再移除该选择。同步写入失败时，会仅回滚仍等于本事务写入值的文件并回读；若并发修改或磁盘错误令回滚无法完整执行，则保留记录并报 `recovery_required`。进程意外退出时也可能已有部分文件恢复，重启后按记录重查并完成；不会声称失败时全部原样未动。发生外部并发改写时保持停止，不覆盖该修改。

生产便携目录在 G 盘时，上述文件全部在该 G 盘目录内。本轮测试的 TEMP、缓存和构建目标均由工作区脚本重定向到 G；测试不写入真实客户端配置或调用新的推理模型。

## 验证

Rust `agent_configs::ownership` 覆盖：八客户端原生配置连续应用、原始基线保留、后加字段保留、密钥不出现在公开报告、漂移与损坏拒绝、预览失效、JSONC/YAML/TOML 注释、原选择清理、路径和 profile 拒绝、组合方案回滚所需的所有权快照。

前端覆盖：展开读取、预览门禁、真实后端令牌传递、冲突拒绝、全局配置锁、旧版本说明与浏览器边界。真实客户端重新加载后的实际行为仍须在当前构建单独验收。
